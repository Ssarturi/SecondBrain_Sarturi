package.json

O que ele é?

É a "lista de compras" do projeto (quais pacotes ele precisa) e também a sua carteira de identidade: nome, versão, arquivo principal e atalhos de comandos.

Por que ele existe?

Para ter um lugar padrão onde o NPM, pessoas e ferramentas descobrem o que é o projeto e do que ele precisa. Assim não é preciso enviar a node_modules: quem baixar o projeto roda npm install e o NPM lê a lista e baixa tudo.

Como criar

npm init -y   // init = inicie um projeto aqui / -y = use as respostas padrão

Exemplo (meu projeto de prática)

{
  "name": "package",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1",
    "start": "node index.js"
  }
}
Campo O que é
name O nome do projeto (vem do nome da pasta)
version A versão do meu projeto
main O arquivo principal, por onde o projeto começa
scripts Atalhos de comandos, rodados com npm run apelido
dependencies Os pacotes que o projeto precisa (o npm install escreve aqui sozinho)

Scripts

O valor de um script é exatamente o comando que eu digitaria no terminal. Ele precisa ficar dentro das chaves de "scripts", e os itens são separados por vírgula (o último não leva vírgula). Com "start": "node index.js", rodo o projeto com npm run start (ou só npm start).

Versão do projeto x versão da dependência

"version" é a versão do meu projeto, que eu mesma mudo ao lançar atualizações. "^1.6.0" nas dependências é a versão do pacote de outra pessoa que meu projeto usa (o ^ aceita atualizações compatíveis).

Rodando um projeto baixado

npm install     // 1º: baixa tudo da lista (recria a node_modules)
npm run start   // 2º: roda o projeto

Lembrete

command not found no terminal = não existe programa com esse nome. Primeiro, conferir se o comando foi digitado certo.
